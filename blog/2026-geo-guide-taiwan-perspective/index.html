2026 GEO 完整指南：台灣站長視角

當搜尋從 Google 的 10 個藍色連結變成 ChatGPT 一段 AI 答案，網站的「被引用權」突然比「被點擊」更值錢。本文拆解 ChatGPT / Claude / Perplexity 引用機制的五個核心訊號，附台灣在地化加分項，並內嵌即時 robots.txt 掃描器讓讀者邊看邊試自家站。

TWTools 編輯部 | 2026-05-20 | 約 10 分鐘

§ 01 為什麼 GEO 突然變成必修

2025 年底前後，全球搜尋行為發生兩個結構性轉變。第一個轉變是 Google 自家在搜尋結果頁面上方放上「AI Overview」答案區，把過去十大藍色連結往下擠。第二個轉變更劇烈——使用者開始把問題直接丟給 ChatGPT、Claude、Perplexity 這些生成式引擎，得到一段附引用連結的答案後就走人，根本不開引用站的連結。

對網站經營者來說，這個變化的意義不只是「流量會掉」，而是「曝光機制變了」。過去十年 SEO 的目標是「衝到第一頁」，現在的目標多了一個——「成為 AI 引擎引用答案時的源頭」。被引用的站即使使用者不點連結，品牌名稱也會出現在 ChatGPT 答案旁邊的小卡片裡。長期下來，那些被頻繁引用的站，會變成讀者腦中「這個領域的權威」。

這套新規則叫做 GEO（Generative Engine Optimization），中文有人翻「生成引擎優化」、有人翻「AI 答案優化」。命名還沒定下來，但遊戲規則已經開跑。AV8D Levelup 在 2025 年底丟出 184 個 AI bot 命中報告，台灣站長看到的數字大概是這樣：GPTBot 命中率最高（97 次 / 14 天）、ChatGPT-User 緊追（54 次）、OAI-SearchBot 第三（21 次）、PerplexityBot 第四（9 次）。光是這四個 bot，就決定了你的內容會不會被 OpenAI 和 Perplexity 兩家最大生成引擎收進答案池。

§ 02 GEO 五個核心訊號

把 ChatGPT / Claude / Perplexity 三家公開的引用機制論文加上實測歸納，AI 引擎挑「要不要引你站」時，大致看五件事——爬蟲開放度、可引用性、結構化資料、E-E-A-T、品牌權威。這五件每一件都能單獨用規則量化，不需要 LLM 主觀打分。

第一件是爬蟲開放度。非常多站架完就忘了開 robots.txt，或者隨手寫了一條 User-agent: * Disallow: / 把所有 bot 全擋掉。這在傳統 SEO 不太嚴重——Googlebot 通常有專屬白名單——但對 AI bot 是致命傷。OpenAI 的 GPTBot、Anthropic 的 ClaudeBot、Perplexity 的 PerplexityBot 全部會乖乖看 robots.txt，被 Disallow 就真的進不去。

第二件是可引用性。AI 引擎寫答案時偏好「能整段拷貝、不用切」的內容。具體規格大致是：每段 40-200 字、結論句放段首、整段含至少一個數字統計、不超過 250 字。寫得長的優點是分析完整，但對 AI 而言就是「沒法直接引」，乾脆換站。

第三件是結構化資料。JSON-LD 是 AI 引擎理解你站結構最快的路徑。最關鍵的是 Organization schema 帶 logo + sameAs 連到至少三個社群（GitHub / Substack / FB / X / IG / Threads / LinkedIn 至少挑三個）。實測 Twtools 自己在 2026 年 5 月加上 site-wide Organization JSON-LD 之後，blog 的 GEO 分從 51 飆到 79（其中品牌權威子指標從 0 直接拿到 75 分滿分附近、多平台訊號從 0 拿到 60）。這是規則式評分系統第一次完整反映實際 schema 改善。

實際 schema 範例不到二十行就能寫完，放在 root layout 一次注入就全站受惠。schema.org 的 Organization type 需要的基本欄位是 name / url / logo（含寬高）/ sameAs（陣列，至少三個社群連結）。logo 一定要給絕對 URL 與正確的寬高屬性，AI 引擎才能正確抓圖；sameAs 必須回連到「真的能找到你」的社群帳號，AI 會去那邊驗證 entity 一致性。Twtools 加上去之後 blog 的「品牌權威」與「多平台訊號」兩個子指標一次拿滿，是因為 sameAs 同時餵了 brand metric（社群連結數量）和 platforms metric（多平台訊號）兩個指標，schema 設計層級的單一改動換到雙指標加分。

第四件是 E-E-A-T。2023 年 Google 在原本的 E-A-T（Expertise / Authoritativeness / Trustworthiness）前面加上 Experience（實際經驗），具體規則變成五件套：作者署名 + 發布日期 + 更新日期 + 至少三條外部引用 + Organization schema。AI 引擎更在乎這個，因為要避免引用 misinformation 翻車。匿名 blog 沒作者沒日期沒引用，幾乎不會被 AI 選為答案來源。

這條的劣勢累積得很快。一個寫了三年沒掛作者署名的個人 blog 即使內容紮實，AI 引擎引用時仍會跳過——因為「無法歸因」對 AI 是高風險訊號。實務上要做的事比想像中少：每篇文章 frontmatter 補 author 欄位、首次發布日期 datePublished、編修後加 dateModified；外部引用三條起跳，文中以 markdown 連結出去即可；站台層級的 Organization schema 上一條已說過。這五件每件都是技術門檻很低的事，但合起來 E-E-A-T 子指標可以從 30 拉到 80+，是投入產出比極高的一輪改動。

第五件是品牌權威。跟 schema 有部分重疊但角度不同——這條看的是「你站背後是不是一個真實 entity」。具體訊號是 sameAs 數量（≥3 個社群連到回來 = 滿分主訊號）、Organization completeness（name / url / logo / sameAs 四件齊全）、健康的內外連結比（internal : external 約 2:1 到 5:1）。AI 引擎引用時會優先選有這些訊號的站，因為被「fly-by-night 內容農場」騙過太多次。

「內外連結比」這條容易被忽略。健康的站台應該是「給的多、拿的少」——文中大量引用外部權威來源（external link），同時站內互鏈完整（internal link）。比例失衡的常見模式是 SaaS 產品站，只連自家文件零外部引用，AI 看到的訊號是「這站不跟世界對話」，引用價值低；另一種失衡是純 affiliate 站，外部連結比內部多十倍，AI 看到的訊號是「這站只是聚合別人的連結」，本身沒原創內容。最健康的比例落在 internal : external 約 2:1 到 5:1 之間，剛好對應「我有自己的內容，但也尊重來源」的姿態。

§ 03 台灣站長獨家加分項：七個在地化訊號

上一節五件是全球通用規則，但台灣站長還有七個獨家加分項，是國際 SEO 工具看不到的——繁體中文比例、TWD 幣別、台灣地址 schema、台灣電話 schema、節氣關鍵字、簡繁混用偵測、台灣縣市地名密度。這些不是傳統意義的「SEO 訊號」，但對 AI 引擎判斷「這站是不是台灣站」極為關鍵。台灣使用者問 ChatGPT「台北市買房怎麼算？」，AI 會優先挑「站台 addressCountry: TW、地址含台北市行政區、提及 TWD」的站當答案來源，而不是隨便一個中國中文站。

繁體中文比例的偵測很簡單——統計頁面內 CJK 字裡有多少是簡體字常見 marker（如「国 / 为 / 这 / 从 / 来 / 给 / 会」等），剩下的就是繁體。低於 95% 繁體就是劣化訊號，可能是內容農場從中國站直翻過來。第二個訊號 TWD 幣別更關鍵：站內若提及人民幣（CNY / RMB / 元）但完全沒提 TWD / NT$ / 新台幣，台灣 AI 答案池幾乎會把你刷掉。

台灣地址 schema 是另一個容易忽略的點。Organization / Place / LocalBusiness 三種 schema 都可以帶 address，但要把 addressCountry 設成「TW」或「Taiwan」AI 才會把你歸到台灣 entity 池。同樣的，telephone 寫成 +886 開頭或 02-xxxx / 03-xxxx / 09xx 格式才是台灣訊號，寫成 +86 或 +1 就會被分到別處。節氣關鍵字（立春 / 清明 / 冬至 等）是文化訊號——AI 引擎引用「2026 清明連假」這類問題時會優先挑提到節氣的站。

最後兩個是負向訊號 + 正向訊號的組合：簡繁混用偵測（頁面同時有簡體字與繁體字 → 扣分），以及台灣縣市地名密度（台灣 / 臺灣 / 台北 / 新北 / 桃園 / 台中 / 高雄 等 25 個地名命中數量）。命中越多（≥5 個獨立地名），AI 引擎對「這站定位明確在台灣」的信心越強。

簡繁混用為什麼要列成獨立指標，而不是併進「繁中比例」？因為兩者抓的是不同問題。「繁中比例」量的是「整篇主要寫繁體還是簡體」——可以判斷「這站是大陸站還是台灣站」；但混用偵測量的是「同一篇內有沒有混雜兩種字體」——這是 AI 內容農場最常見的劣化模式（用 LLM 直翻簡體 → 半路繁化沒做乾淨），即使整體繁體比例 92%，只要有 5+ 個簡體字命中就會被本指標扣分。實務上這條最常見的失誤不是內容農場，而是繁體站台引用了大陸來源的句子卻沒人工潤過——比例上看起來無傷，但 AI 引擎抓的是 marker 命中，仍會被判定低品質。

節氣關鍵字背後的邏輯也比表面看起來深。AI 引擎在中文世界引用時的對手不只是台灣站，還有大陸站、香港站、新馬華文站。「節氣」是台灣與大陸華文圈共享的文化錨點，但在台灣語境下會搭配「清明連假」「冬至湯圓」「立春開工日」這類在地實作；大陸站則搭配「清明掃墓 + 國家放假辦法」這類官方語境。AI 引擎透過節氣關鍵字 + 周圍語境一起判斷你站到底屬於哪個文化圈。所以光提到「立春」不夠，要搭配「2026 清明連假四天」「中秋三天連假」這類台灣放假慣例語境才會被歸到台灣 entity 池。

§ 04 實戰閉環：Twtools 自己怎麼跑

2026 年 5 月 20 日，Twtools 在 BaseLayout 注入了 site-wide Organization JSON-LD，包含完整 logo + 三個 sameAs（github.com/dvdmaru / dvdmaru.substack.com / aire.twtools.cc）。同時在 Aire 子站（aire.twtools.cc）的 root layout 加上 default canonical 解決 Next.js client component 無法 export metadata 的限制。

落地後同日跑三個樣本對比改善前後分數，結果是這樣：Twtools 首頁 GEO 從 40 飆到 67（+27 分）、Twtools blog 從 51 飆到 79（+28 分，子指標品牌權威 0→75 / 多平台訊號 0→60 / E-E-A-T +15 / 結構化資料 +15 全面拿分）、Aire 首頁 SEO 從 85 升到 94（+9 分，技術 SEO 70→100，canonical 補齊一次拿滿）。三個樣本同向上升、子指標精準命中預期，驗證「規則式評分系統能反映實際 schema 改善」的前提成立。

這個閉環的意義是——你不需要等 Google Search Console 七天後跑出新數據才知道改對沒，純規則式評分當下就能看出來。對個人站長與一人公司，這是極大的差距：傳統 SEO 工具如 Ahrefs / SEMrush 月費 99 美金起，本工具完全免費、無 quota、無 email 登入。

Aire 子站的 canonical 補完是另一個值得單獨講的案例。Next.js App Router 的常見坑：root page.tsx 寫了 'use client' 就無法 export metadata（因為 server-only），但 client component 是首頁互動的剛性需求拿不掉。解法是把 canonical 搬到 app/layout.tsx 的 alternates.canonical = '/'，當 default 值，其他 page 若需要 explicit 覆寫就照原樣 export。這個 fix 對 Aire 的「技術 SEO」子指標從 70 拉到 100（+30 分），單一指標一次拿滿——同樣是設計層級的單一改動換到指標滿分的範例，跟前面 Twtools Organization schema 的雙指標加分形成「站台層級 schema 動一條、多指標一起受惠」的雙案例對照。

§ 05 下一步行動清單

讀到這裡，給你一個排好優先級的具體清單。每件事都對應上面拆過的某個訊號，不是無中生有的建議。台灣站長可以照著走一遍，最少投入 1-2 小時就能看到 GEO 分數明顯上升。

  1. 檢查 robots.txt 對 10 個 AI bot 的開放度。用上面的嵌入式工具掃一次，看看 GPTBot / ChatGPT-User / OAI-SearchBot / ClaudeBot / anthropic-ai / Google-Extended / PerplexityBot / CCBot / Bytespider / Applebot-Extended 哪幾個被擋。被擋的全部 Allow 回來。
  2. 加 site-wide Organization JSON-LD。在站台 root layout（Astro 是 BaseLayout、Next.js 是 layout.tsx）注入，包含 name / url / logo / sameAs（至少三個社群連結）。這一步是台灣站投入產出比最高的單一動作。
  3. 每篇 blog 補三件套。作者署名 + 發布日期 + 更新日期，外加至少三個外部 reference 連結。沒有 BlogPosting schema 的補上 BlogPosting schema。
  4. 把段落改寫成 40-200 字。長段落拆短、結論句搬到段首、每段塞至少一個數字。不需要全文重寫，做幾個試點段落就能看效果。
  5. 台灣站長獨家加分。頁面內提及 TWD / NT$、Organization.address.addressCountry 設「TW」、telephone 寫 +886 格式、適度提及節氣與台灣縣市地名。這七個訊號是國際 SEO 工具掃不到的，但對台灣 AI 答案池命中率影響很大。

最後一個建議——量化你的進度。每改完一步就用本站的 SEO / GEO / AEO 三軸測評工具 跑分，看哪個子指標升了多少。Twtools 內建 localStorage 歷史追蹤，不需要登入就能存歷次分數變化。GEO 跟 SEO / AEO 一樣，是可以量化、可以追蹤、可以驗證的長期工程，不是玄學。
